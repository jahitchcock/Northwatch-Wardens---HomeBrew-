Guide the user through syncing edits made on the Homebrewery website back to this repository's source files.

This command handles the **Homebrewery → repo** direction of the round-trip workflow. For the **repo → Homebrewery** direction, just run `/build`.

---

## Before you start

Ask the user which guide they edited:
- **Player's Guide** → file is `build/The-adventurers-guide-to-aevoria.txt`
- **DM's Guide** → file is `build/A-DMs-guide-to-aevoria.txt`
- **Both** → handle each in sequence

---

## Step 1 — Verify the repo is in a clean state

Run `git status` and check for uncommitted changes. If there are uncommitted changes to source files, advise the user to commit or stash them first — this creates a clean checkpoint to diff against after syncing.

```bash
git status
git stash   # if needed
```

## Step 2 — Confirm the downloaded file is in place

Check that the `.txt` file the user downloaded from Homebrewery has been placed in `build/`:
- Verify the file exists and its modification time is recent
- Warn if the file looks like it's from an old build (has no `<!-- FILE_START:` markers)

If no markers are found in the downloaded file, **stop and explain**: the user either downloaded from an older brew that was uploaded before the marker system was in place, or they are looking at the wrong file. Instruct them to:
1. Build fresh: `./build.sh --players` (or `--dms`)
2. Upload the new `.txt` to Homebrewery, re-apply edits, re-download

## Step 3 — Run the unbuild

```bash
./build.sh --unbuild-players   # or --unbuild-dms
```

Report which files were updated vs unchanged.

## Step 4 — Review the diff

Run `git diff` on the updated source files and summarize the changes to the user:
- Which files were modified
- Approximate nature of changes (added content, removed content, reformatted)
- Flag any unexpected changes (e.g., watercolor stain tags appearing in source files — these indicate the stain-stripping didn't fully clean a mid-file waterstain)

If stain tags appear in the diff, offer to clean them:
```bash
# Strip any remaining {{watercolor...}} tags from modified files
```

## Step 5 — Verify round-trip integrity

Run `./build.sh --players` (or `--dms`) and confirm the build succeeds without errors. This catches broken markdown introduced during Homebrewery editing.

## Step 6 — Commit

Once the user is satisfied with the diff, commit the source file changes:
```bash
git add [modified source files]
git commit -m "Sync Homebrewery edits back to source: [brief description of changes]"
```

---

## Important notes

**What syncs back:**
- All text edits made in the Homebrewery editor
- Formatting changes (Homebrewery markdown syntax)
- Content additions and deletions within existing sections

**What does NOT sync back (and shouldn't):**
- Front cover, metadata block, CSS block — these are generated by `build.js` from TOC JSON
- Table of contents — auto-generated
- Page footers (`{{pageNumber,auto}}` / `{{footnote ...}}`) — managed by `add_page_footers.py`
- Watercolor stains — auto-injected by build, stripped on unbuild
- Chapter/section headings injected between files by the build system

**If you added a new section in Homebrewery** that doesn't correspond to an existing source file, unbuild cannot place it anywhere. In that case, create the new source file manually and add it to the TOC JSON.
